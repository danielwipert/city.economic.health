# Working with me on this project

I code mostly in Python. Take things step by step, don't assume I know how to
do everything, and break tasks into simple steps.

## Logic gates (how to ask for decisions)

I get overwhelmed by a lot of data and by being asked to choose several things
at once. When a path forward needs my decision, don't write one long answer
with a big decision at the end.

- Break the decision into small **gates**, and ask **one gate at a time**.
  Never stack several decisions in one message.
- Each gate gives **three clear options** (four at most), labeled A, B, C
  (and D), readable in about one minute, with enough context to decide.
- Mark the recommended option and say why in a few words.
- Keep each option to one or two lines: what it means and what it leads to.
- When there are several gates, show the path first (numbered list, current
  gate marked).
- After I pick, lock it in with one line ("Locked in: B, ..."), then move to
  the next gate.
- I may tweak an option ("A, but ..."); restate it and move on. If none of the
  options fit, I'll say so — reframe the gate. If a gate feels too big, split it.
- Keep everything else short. Background goes in documents, not in the gate.
- When the gates are done, record the decisions in `DECISIONS.md`
  (date, decision, why, and where it lives).
